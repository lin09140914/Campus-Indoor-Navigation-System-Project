# 3D / Rendering Team Development Specification — V0.1

> 狀態：實作規格草案。此文件涵蓋地圖與路線視覺化；資料契約以 `Data_Specification.md` 為準。

## 1. 文件目的與版本
定義將標準地圖和路線資料轉為可讀、可互動的 2D/3D 場景之要求，並約定 `renderMap()`、`renderRoute()`。

## 2. 組別任務與範圍
負責 SVG/樓層場景載入、視角與樓層呈現、路線疊加、互動狀態與效能。地圖資料由地圖組提供，Route 由路徑組提供；目的地選擇與定位狀態由 UI 協作整合。

## 3. 使用情境與系統流程
載入 Floor 與 SVG → 建立場景 → 顯示目前樓層與定位 → 取得 Route → 將 Route node/edge 轉成場景幾何 → 高亮路線與起終點 → 隨樓層切換更新。

## 4. 輸入資料與前置條件
`renderMap()` 接受 SVG、Floor 及顯示設定；`renderRoute()` 接受 Route、Graph 與已載入場景。資料的 `building_id`、`map_version`、`coordinate_system_id` 必須一致；容器/渲染引擎可用且尺寸有效。

## 5. 輸出資料與品質要求
函式產生可供 UI 使用的場景/渲染控制結果，包含成功狀態及錯誤；避免將函式內部引擎物件寫入共用資料契約。路線須與地圖幾何對齊，樓層切換時不顯示錯層路段。

## 6. 跨組介面與資料依賴
`renderMap()`、`renderRoute()` 為共用 API。依賴 SVG、Floor、Route、Graph 欄位契約。定位結果若呈現，由 UI/場景整合呼叫；介面不自行推算導航路徑。

## 7. 設計與實作規範
- 使用 Floor `svg_transform` 將 SVG 座標轉為建築 XZ 座標，並以 `elevation_m` 作 Y 高度；縮放/旋轉須一致套用於地圖、位置標記與路線。
- SVG 必須安全解析；限制外部資源與不必要腳本。缺少視覺元素不得改變路徑拓樸。
- Route 以 node/edge 對應幾何繪製，方向箭頭與樓層連接清楚可辨；提供目前樓層篩選。
- 支援容器尺寸變動、重新載入及清理資源；呈現結果應可由呼叫端控制/更新。

## 8. 錯誤處理與特殊情況
無效 SVG、缺失 ID、地圖版本不符、Route 指向不存在節點、空容器或 WebGL/3D 能力不足時回報可處理錯誤，必要時降級至 2D。不得把錯誤轉成空白而無狀態回傳。

## 9. 測試與驗收
檢查不同樓層、座標轉換、縮放、旋轉、路線對齊、起終點、跨樓層切換、缺圖形及 2D 降級。以多尺寸容器和目標裝置驗證清晰度、互動及資源釋放；效能門檻另以實機量測制定。

## 10. 交付物、相依與待決事項
交付兩個共用函式、場景更新/清理方法、錯誤回報、示例頁及裝置驗證紀錄。待決：無障礙呈現、樓層高度與跨樓層動畫規則（3D 引擎已定為 Three.js，見 `Technology_Stack.md`）。
