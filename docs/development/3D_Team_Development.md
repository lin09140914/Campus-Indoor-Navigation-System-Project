# 校園室內導航系統 V1 — 3D 組開發規格書

**文件版本：** V0.1（草案）  
**負責組別：** 3D 視覺化組（3D Visualization Team）  
**適用範圍：** V1  
**狀態：** 待跨組資料規格確認

---

## 1. 開發目標

3D 組負責使用 Three.js，將地圖組提供的 SVG 平面圖轉換為可互動的地圖視覺化場景，並將路徑組提供的導航路線疊加顯示。

本組 V1 的核心任務為：

1. **地圖渲染：** 支援單樓層與多樓層地圖，並允許使用者以 360 度旋轉方式查看地圖。
2. **導航路線渲染：** 在地圖場景中疊加路線，正確呈現其位置與樓層。
3. **渲染正確性測試：** 驗證地圖及路線與原始資料的一致性。

所有地圖與路線渲染必須使用全專案統一資料格式。

3D 組不負責 SVG 原始資料建構、A\* 演算法、定位演算法或 UI 操作流程設計。

## 2. 工作範圍與交付成果

| 工作項目 | 交付成果 | V1 要求 |
| --- | --- | --- |
| 單樓層地圖渲染 | 單樓層 3D 地圖顯示 | 必須 |
| 多樓層地圖渲染 | 多樓層 3D 地圖顯示 | 必須 |
| 360 度視角旋轉 | 可互動的地圖視角 | 必須 |
| 路線疊加渲染 | 地圖上的導航路線 | 必須 |
| 統一 SVG 支援 | 能使用標準 SVG 資料 | 必須 |
| 統一 Route 支援 | 能使用標準路線資料 | 必須 |
| 渲染正確性測試 | 測試程式及測試結果 | 必須 |

地圖與路線應在同一場景中呈現，但其渲染功能需要可以分別使用。

## 3. 主要 Function 規格

### 3.1 renderMap()

**功能：** 使用統一 SVG 及相關樓層資訊，渲染單層或多層地圖。

### Input

| 輸入 | 說明 |
| --- | --- |
| 統一 SVG | 地圖組提供的各樓層平面圖 |
| 樓層資料 | 樓層識別及相關空間資訊 |
| 顯示設定 | 單樓層、多樓層及視角等顯示需求 |

### Output

地圖視覺化結果，可供 UI 組顯示及操作。

必要功能：

- 顯示單樓層地圖。
- 顯示多樓層地圖。
- 提供 360 度視角旋轉。
- 正確呈現地圖空間與樓層關係。

實際參數及輸出介面，待跨組規格確認。

### 3.2 renderRoute()

**功能：** 在已建立的地圖場景上疊加導航路線。

### Input

| 輸入 | 說明 |
| --- | --- |
| 統一 Route | 路徑組提供的導航路線 |
| 已載入的地圖場景 | 地圖渲染 Function 所建立的視覺化場景 |

### Output

疊加導航路線後的視覺化結果。

必要功能：

- 將導航路線顯示於正確的空間位置。
- 讓導航路線與地圖保持座標一致。
- 支援同樓層與跨樓層路線顯示。
- 不因更新路線而破壞既有地圖顯示。

地圖與路線的內部渲染方式由 3D 組自行決定。

### 基本處理流程

1. 接收統一 SVG 與樓層資料。
2. 建立單層或多層地圖場景。
3. 提供地圖視角旋轉操作。
4. 接收統一 Route。
5. 將 Route 的座標與樓層對應至場景。
6. 在地圖上疊加導航路線。
7. 將視覺化結果提供給 UI 組。

### 異常情況

需要能識別：

- SVG 資料缺失或無效。
- 樓層資料不存在。
- 地圖渲染失敗。
- Route 資料無效。
- 路線無法正確對應地圖。
- 路線渲染失敗。

詳細錯誤回報格式依全專案例外處理規範統一。

## 4. 統一資料規格

### 4.1 SVG 平面圖

**資料提供者：** 地圖組  
**資料使用者：** 3D 組

3D 組必須使用全專案統一 SVG 格式，確保能正確呈現各樓層的建築平面結構。

### 4.2 統一座標系統

SVG、Graph、Route 與 3D 場景必須具有一致的空間對應關係。

3D 組需依統一座標定義進行渲染，不得自行改變原始空間座標的意義。

### 4.3 Route 路線格式

**資料提供者：** 路徑組  
**資料使用者：** 3D 組

Route 必須能正確表示路線經過的位置、節點順序與樓層資訊，以供場景中的路線疊加。

### 4.4 樓層資料

必須遵守統一樓層編號與空間對應規則，確保單樓層、多樓層及跨樓層路線顯示一致。

### 4.5 定位結果

3D 場景如需呈現使用者位置，必須使用定位組提供的統一定位結果與座標規範。

具體位置標記的獨立介面及操作方式，留待跨組介面確認。

本節正式欄位、型別與資料結構，以全專案八項統一資料規格為準。

## 5. 跨組交接

| 相關組別 | 交接資料或功能 | 用途 |
| --- | --- | --- |
| 地圖組 | SVG、樓層及座標資料 | 建立 3D 地圖 |
| 路徑組 | 統一 Route | 渲染導航路線 |
| 定位組 | 統一定位結果 | 必要時顯示使用者位置 |
| UI 組 | 呼叫渲染 Function | 顯示地圖與路線 |
| UI 組 | 顯示及互動需求 | 控制視覺化內容 |

3D 組負責渲染功能，UI 組負責整合及提供使用者操作介面。

## 6. 開發環境與依賴

3D 組確定使用：

- **主要渲染引擎：** Three.js。
- **渲染程式語言：** JavaScript。
- **IDE：** 自由選擇。
- **目標平台：** 專案 Android App。

由於 Three.js 使用 WebGL，需與 Android 應用程式的視覺化承載環境相容。

目前規劃透過 Android WebView 進行整合，但正式橋接方式及相關版本，留待系統整合架構確認。

其他開發依賴由 3D 組自行選擇，但須符合專案開發規範。

## 7. 測試與驗收要求

### 7.1 地圖渲染測試

| 測試項目 | 驗收方向 |
| --- | --- |
| 單樓層渲染 | 正確顯示單層地圖 |
| 多樓層渲染 | 正確呈現不同樓層 |
| 360 度旋轉 | 可以自由旋轉地圖視角 |
| SVG 正確性 | 地圖結構與原始 SVG 一致 |
| 座標一致性 | 地圖空間位置與統一座標對應 |
| 樓層一致性 | 不同樓層的位置與相對關係正確 |

### 7.2 路線渲染測試

| 測試項目 | 驗收方向 |
| --- | --- |
| 同樓層路線 | 路線顯示在正確位置 |
| 跨樓層路線 | 不同樓層的路線顯示正確 |
| 路線座標 | Route 與地圖對齊 |
| 路線更新 | 不破壞已建立的地圖 |
| 無效 Route | 能辨識無法渲染的資料 |

### 7.3 測試結果紀錄

需要保存：

- 測試使用的 SVG、樓層與 Route。
- 預期視覺化結果。
- 實際渲染結果。
- 是否符合地圖與路線座標規格。
- 發現的偏移、缺失或異常。

具體測試方式及驗收門檻，後續統一制定。

## 10. V1 完成條件

3D 組完成 V1 必須達成：

1. 完成 `renderMap()` 地圖渲染 Function。
2. 完成 `renderRoute()` 路線渲染 Function。
3. 使用統一 SVG 正確渲染單樓層與多樓層地圖。
4. 支援 360 度視角旋轉。
5. 使用統一 Route 將導航路線正確疊加於地圖。
6. 完成地圖與路線渲染正確性測試。
7. 將渲染功能提供給 UI 組使用。
8. 符合專案開發規範及共通資料規格。

3D 組可以自主決定內部場景管理、輔助函式及渲染實作方式，但不得違反已確認的跨組介面與資料規範。
