# Route Team Development Specification — V0.1

> 狀態：實作規格草案。Graph、Route 與 Destination 欄位以統一資料規格為準。

## 1. 文件目的與版本
定義由目前位置到目的地計算可行路線的實作要求，並固定跨組 `findRoute()` 契約。

## 2. 組別任務與範圍
負責 Graph 路徑搜尋、限制條件、路線成本、無路徑處理及步驟資料。地圖拓樸由地圖組提供；位置由定位組提供；路線呈現由 3D/UI 組處理。

## 3. 使用情境與系統流程
取得定位結果與目的地 → 驗證樓層/節點/圖版本 → 將起終點映射到 Graph → 套用移動方式與限制 → 搜尋路徑 → 產生 Route 與摘要 → UI/渲染組呈現。

## 4. 輸入資料與前置條件
必要：Graph、有效 Localization Result、Location ID、移動方式 `any | stair | elev`。Graph、定位與目的地必須使用相同 `building_id`、`map_version`、`coordinate_system_id`；跨樓層目的地須有可達的樓層連通邊。

## 5. 輸出資料與品質要求
成功時回傳 Route：`path`、等效成本 `length`、依序 `floors` 及 `transitions`。無可達路徑時回傳 `null`；輸入無效或執行失敗交由全專案例外處理規範。

## 6. 跨組介面與資料依賴
`findRoute()` 為跨組函式。目的地以 Location `id` 傳入；結果依統一 Graph/Route 結構輸出。渲染端依 Route `path` 節點及 Graph edge 對照地圖。

## 7. 設計與實作規範
- 搜尋僅使用 Graph 中有效且符合通行條件的邊；樓層及無障礙條件納入可行性判斷。V1 Graph 為無向圖，所有邊可雙向通行，不處理方向性與臨時封閉。
- 預設成本可使用距離；其他偏好（少轉彎、避樓梯）需明確作為選項並記錄算法/成本語意。
- 起點為座標時，需以地圖映射至合法節點並保留映射方式；遠離可走區時回傳無效起點。
- Route 的每一相鄰節點對應 Graph 邊，路線總長可重算驗證。

## 8. 錯誤處理與特殊情況
起終點不存在、圖版本不一致、跨樓層不連通、移動限制使路徑不可行、空圖或損壞圖均回傳可辨識狀態。若起點定位信心不足，回傳需要重新定位/確認的結果或由呼叫端決策，不能靜默選遠端節點。

## 9. 測試與驗收
以已知最短路徑驗證距離與節點序列；測試同樓層、跨樓層、替代路徑、無障礙模式、無解及錯版資料。驗證每條 Route edge 存在且總成本一致；效能門檻依目標裝置與 Graph 規模另定。

## 10. 交付物、相依與待決事項
交付 `findRoute()`、選項與成本文件、錯誤狀態、測試案例及效能摘要。待決：目的地到 Graph 節點的正式映射、路線偏好權重及步驟文案格式。
