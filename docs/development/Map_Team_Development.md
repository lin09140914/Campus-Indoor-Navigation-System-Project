# Map Team Development Specification — V0.1

> 狀態：實作規格草案。跨組資料依 `docs/interfaces/schemas/Data_Specification.md`；共用函式依 `docs/interfaces/functions/function.md`。

## 1. 文件目的與版本
定義地圖組將校園室內平面圖轉成可供定位、路徑規劃與視覺呈現使用的標準地圖資料。版本 V0.1，變更需記錄版本、日期、原因及相容性。

## 2. 組別任務與範圍
負責來源圖資清理、SVG 正規化、統一座標校準、可通行區與障礙建模、拓樸 Graph 製作，以及離線地圖品質評估。UI、定位與路徑演算法不屬本組，但需提供其所需資料。

## 3. 使用情境與系統流程
以樓層為單位匯入來源圖 → 清理圖層與幾何 → 建立標準 SVG → 校準座標 → 標註房間、通道、出入口、樓梯及電梯 → 建立 Graph → 驗證拓樸與誤差 → 發布版本化地圖套件。

## 4. 輸入資料與前置條件
- 原始平面圖（優先 SVG；其他格式先轉換並保留來源）。
- 樓層識別、比例尺或已知控制點、樓層間連通設施及禁止通行區資料。
- 現場量測控制點與地圖特徵對應。無可靠比例或控制點時不得宣稱公尺級精度。

## 5. 輸出資料與品質要求
依統一契約輸出 SVG、Floor、Graph、Node Mapping；每個實體以穩定 ID 串接。所有可走邊須連接有效節點、不得跨越障礙；跨樓層邊須標示連通設施及兩端樓層。地圖套件需包含版本、來源、座標參考、校準資料及品質報告。

## 6. 跨組介面與資料依賴
下游依 `building_id`、`map_version`、`coordinate_system_id`、整數 `floor` 及 `id` 關聯資料，不以顯示文字或陣列順序作為識別。`renderMap()` 使用 SVG/Floor；`findRoute()` 使用 Graph；Node Mapping 以 `node_id` 對到 SVG `svg_anchor_id`。契約異動需與介面維護者協調。

## 7. 設計與實作規範
- SVG 使用 `viewBox`、標準圖層 ID 及 `data-building-id`/`data-floor`/`data-map-version`。依 Floor 的 `svg_transform` 與唯一公式轉為建築局部 XZ 座標；世界垂直高度為 `floor.elevation_m`。
- 幾何元素須具語意標籤或穩定 ID；裝飾圖形不應成為可走路網。
- Graph 節點使用 `id,x,z,floor,type`，邊使用 `a,b,w,kind`；V1 為無向圖。`w` 是等效距離且不得小於兩端 XZ 直線距離，以維持 A* 啟發函式有效。
- 障礙、無障礙限制與樓層連通性採明確欄位表示，不依賴名稱猜測。V1 Graph 為無向圖，不含方向性欄位。
- `evaluateMapError()` 為本組離線內部函式：比較控制點實測位置與地圖映射位置，輸出樣本數、平均/最大誤差及單位；不是跨組 API。

## 8. 錯誤處理與特殊情況
來源缺比例、控制點不足、幾何損壞、孤立節點、重複 ID、無效樓層引用及不連通區域均列入品質報告。不得靜默修補可能改變拓樸的資料；以問題清單回報並保留原始來源。不同樓層各自校準，不假設座標原點相同即代表可連通。

## 9. 測試與驗收
- SVG 可解析且符合座標、ID 與樓層契約。
- Graph 所有引用有效；邊長非負且與幾何合理；禁止區域不可穿越。
- 測試各樓層孤島、出入口、樓梯/電梯連接及無障礙限制。
- 以控制點執行 `evaluateMapError()`，報告誤差分布、量測方法與樣本；驗收門檻由場域量測後另行核定，不預設虛構精度。
- 套件可被定位、路徑及渲染組依契約讀取。

## 10. 交付物、相依與待決事項
交付版本化樓層 SVG、Floor/Graph/Node Mapping、來源與校準紀錄、品質報告及變更摘要。相依現場圖資與量測。待決：最終投影/原點、精度門檻、圖資授權、障礙物更新責任及無障礙屬性範圍。
