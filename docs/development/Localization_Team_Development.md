# 校園室內導航系統 V1 — 定位組開發規格書

**文件版本：** V0.1（草案）  
**負責組別：** 定位組（Localization Team）  
**適用範圍：** V1  
**狀態：** 待跨組資料規格確認

---

## 1. 開發目標

定位組負責利用手機感測器資料及室內定位演算法，自動估計使用者在建築物內的位置，並提供給其他組別使用。

本組 V1 的核心任務為：

1. **自動原地定位：** 使用者在室內保持原地時，利用感測器及定位演算法估計位置，輸出統一格式的定位結果。
2. **定位精準度評估：** 透過實際測試，計算定位誤差並產生測試報告。

完成 V1 後，可進一步處理使用者移動期間的連續定位與累積漂移問題。

定位組不負責地圖建構、路徑規劃、3D 渲染及 UI 開發。

## 2. 工作範圍與交付成果

| 工作項目 | 交付成果 | V1 要求 |
| --- | --- | --- |
| 手機感測器資料取得與處理 | 定位演算法所需資料 | 必須 |
| 自動原地定位 | 定位 Function | 必須 |
| 統一定位結果輸出 | 符合共通規格的定位結果 | 必須 |

V1 不要求使用者手動設定起點座標，也不要求行走期間持續更新位置。

## 3. 主要 Function 規格

### 3.1 getCurrentPosition()

**功能：** 使用手機感測器資料與定位演算法，自動估計使用者所在位置。

**暫定 Function：** `getCurrentPosition()`

### Input

| 輸入 | 說明 |
| --- | --- |
| 感測器資料 | 定位演算法所需的手機感測資訊 |
| 定位參考資料 | 定位演算法所需的地圖或其他參考資料 |

實際使用哪些感測器，由定位組依演算法需求決定。

### Output

輸出符合全專案統一定位結果格式的資料。

預期包含：

- 使用者所在位置的座標。
- 使用者所在樓層。
- 定位 Confidence。

具體欄位名稱、型別、數值範圍與單位，依統一定位結果規格決定。

### 基本處理流程

1. 取得定位所需的感測器資料。
2. 進行必要的資料處理。
3. 使用定位演算法估計使用者位置。
4. 將估計結果轉換至統一座標系統。
5. 輸出標準化定位結果。

### 異常情況

需要能識別：

- 感測器資料不足或無法使用。
- 必要定位參考資料不存在。
- 定位失敗。
- 定位結果可信度不足。
- 定位計算發生錯誤。

詳細錯誤回報格式，依後續全專案例外處理規範決定。

## 4. 統一資料規格

### 4.1 統一座標系統

**相關組別：** 全部五組

定位組輸出使用全專案共同的建築物局部座標系，水平座標 `x`、`z` 的單位為公尺，並附上整數 `floor`；不得將 SVG 圖面單位直接當成公尺輸出。

- **原點：** 1F SVG `viewBox` 左上角 `(u0,v0)` 對應全棟建築物的 `(x,y,z) = (0,0,0)`；1F 地坪基準高度為 `y = 0`。
- **軸向：** 以 1F SVG 向右為 `+x`、向下為 `+z`，垂直向上為 `+y`。不同樓層共用相同的水平原點與軸向，以 `floor` 對應樓層高度。
- **與地圖組對齊：** `getCurrentPosition()` 的 `position.x`、`position.z` 必須與同版本 Graph 的建築物座標一致。實測比例尺與其他樓層的圖面對齊完成前，不得宣稱 SVG 圖面座標已是公尺座標。

完整轉換公式與樓層資料欄位以[統一資料規格](../interfaces/schemas/Data_Specification.md)為準。

### 4.2 定位結果格式

**資料提供者：** 定位組  
**資料使用者：** UI、路徑、3D 組

定位結果必須使用統一格式，讓路徑組能將位置匹配至導航圖，並讓 3D 組能正確顯示使用者的位置。

### 4.3 樓層資料

定位組必須採用全專案統一的樓層識別方式，不得自行定義與其他組別不相容的樓層編號。

### 4.4 Confidence 定義

必須明確定義定位 Confidence 的意義、允許範圍及判讀方式。

單次定位的 Confidence 不等同於利用實際參考位置測量的定位誤差。

正式欄位與資料結構，以全專案八項統一資料規格為準。

## 5. 跨組交接

| 相關組別 | 交接資料 | 用途 |
| --- | --- | --- |
| 地圖組 | 統一座標與必要的地圖參考資訊 | 將定位結果對應至建築空間 |
| UI 組 | 定位結果 | 提供使用者導航起點 |
| 路徑組 | 定位結果 | 匹配導航節點並進行路徑計算 |
| 3D 組 | 定位結果 | 顯示使用者所在位置 |

定位組負責產生位置資訊，不負責將位置繪製到 3D 場景。

## 6. 開發環境與依賴

定位組應符合全專案的 Android 應用程式架構。

開發原則：

- App 端以 Kotlin 作為建議主要語言，實際版本依共用環境規範。
- 可使用 Android 原生感測器 API。
- 定位演算法與必要的 Library 由定位組自行選擇。
- IDE 自由選擇。
- 第三方依賴必須符合專案的相容性及開發規範。
- 跨組資料必須符合統一格式。

實際感測器種類、演算法與依賴版本，由定位組在正式開發前列明。

## 7. 測試與驗收要求

### 7.1 定位功能測試

| 測試項目 | 驗收方向 |
| --- | --- |
| 自動定位 | 不手動輸入初始座標即可估計使用者位置 |
| 不同位置定位 | 可在測試範圍內的不同位置執行定位 |
| 樓層識別 | 能依統一樓層規格提供定位結果 |
| 座標輸出 | 符合統一座標系統 |
| Confidence | 輸出符合正式定義 |
| 異常輸入 | 能辨識定位失敗與資料不足 |

### 7.2 定位精準度測試

應在已知實際位置的測試點執行定位，並計算定位結果與參考位置的差異。

至少記錄：

- 實際參考位置。
- 演算法估計位置。
- 定位誤差。
- 測試樓層與位置。
- 多次測試的誤差統計。

### 7.3 測試結果紀錄

測試報告應能用於判斷定位方法是否符合 V1 需求。

實際測試點數量、定位誤差門檻及統計指標，後續統一制定。

## 8. 後續擴充：移動定位

完成 V1 後，可進一步研究：

## 10. V1 完成條件

定位組完成 V1 必須達成：

1. 完成 `getCurrentPosition()` 定位 Function。
2. 使用感測器資料及定位演算法進行自動原地定位。
3. 不要求使用者手動輸入起點位置。
4. 輸出符合統一格式的定位結果。
5. 完成定位精準度測試並提交誤差報告。
6. 遵守統一座標、樓層及開發規範。

移動定位、持續追蹤及漂移修正不列入 V1 必要驗收。

內部演算法、輔助函式及開發工具由定位組自行決定，但必須遵守專案開發規範。
